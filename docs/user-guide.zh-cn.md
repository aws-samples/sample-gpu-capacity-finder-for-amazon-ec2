# GPU Capacity Finder 用户指南

> 本文档是[英文版](user-guide.md)的直译，不含额外内容。如有出入，以英文版为准。

如果您登录 GPU Capacity Finder，在 Amazon Elastic Compute Cloud（Amazon EC2）上寻找图形处理器（GPU）容量，本指南就是为您准备的。部署该页面的人员另有一份[管理员指南](admin-guide.zh-cn.md)。

## 此工具回答什么

GPU Capacity Finder 回答一个问题：您现在或近期可以在哪里、以什么方式获得所需的 GPU 实例？它读取您的账户已启用的区域（减去管理员排除的区域）以及各 GPU 实例系列的容量信号，并允许您用一次测试启动来验证某个信号。它不管理实例，不预留容量，也不启动您的工作负载：当您决定行动时，您在 EC2 控制台中购买 Capacity Block，并在 EC2 控制台中预留容量，或使用页面提供给您复制的 AWS Command Line Interface（AWS CLI）命令预留。

页面有六个标签页，每项任务一个，顺序如下：

- **Spot 分数** 以表格或地图的形式，按每个 GPU 组的 Spot 放置分数比较各区域。
- **按需与 Spot** 显示一个区域中的一个实例类型：按需定价、Spot 分数、测试启动面板，以及每个可用区的 Spot 价格，并附有预留容量的命令。
- **Capacity Block** 同时在多个区域和实例类型中搜索您可以购买的 Capacity Block 方案，并查找当前提供的最大实例数量。
- **配额** 显示您的服务配额以及各项的已用量，因为配额可能在容量成为问题之前就阻止启动。
- **提醒** 列出您的电子邮件提醒。只有在管理员开启电子邮件提醒时才会显示。
- **用户** 说明如何在 Amazon Cognito 控制台中添加、更新和删除用户。普通用户不需要它。

每个答案都只反映某一时间点：它描述的是检查的那一刻，而不是未来。

## 登录与首次设置

管理员会为您创建用户。自助注册已关闭。

1. 查找一封包含您的用户名和临时密码的电子邮件。临时密码在七天后过期。如果已过期，请让管理员重新发送。
2. 打开管理员提供给您的网站 URL，选择 **登录**。页面会将您转到 Amazon Cognito 登录页面。
3. 使用您的电子邮件地址和临时密码登录。
4. 设置新密码。密码至少需要 12 个字符，并包含一个大写字母、一个小写字母、一个数字和一个符号。
5. 设置多重身份验证（MFA）。登录页面会显示一个二维码。使用支持基于时间的一次性密码（TOTP）的身份验证器应用扫描它，然后输入应用中的六位数代码。本示例只接受身份验证器应用，不接受短信。
6. 页面会打开第一个标签页。

之后每次登录时，您需要输入密码和身份验证器应用中的当前代码。如果您忘记了密码，请在登录页面上选择 **Forgot your password?**；验证码会发送到您的电子邮件地址。

默认情况下，您的会话最长持续 12 小时；时长由管理员设置。只要标签页保持打开，页面就会在后台续期您的登录。页面只为当前浏览器标签页保存您的登录，因此关闭标签页就会退出登录。选择右上角的 **退出登录** 可结束会话。

页眉中有语言切换器，可选择英文、繁体中文和简体中文。页面会在此浏览器中记住您的选择，在地址中加上 `?lang=en-US`、`?lang=zh-TW` 或 `?lang=zh-CN` 也可以选择语言。

## 页面概览

每个标签页的页眉中都有自己的控件，例如 **区域** 列表。页面会在此浏览器中记住您上次使用的区域和实例类型，并在其他标签页中将它们用作初始选择。

标签页会在您第一次打开它时加载数据，并在您更改其选择时再次加载。请求运行期间，顶栏下方会显示一条细的橙色进度条。启动某项操作的按钮会显示一个加载图标和 `正在测试...` 之类的文字，直到操作完成。请求失败时，原本显示数据的位置会出现一条红色消息，并附有 **重试** 按钮。当标签页只有一部分失败时，消息会指出是哪一部分，标签页的其余部分仍会显示。地址栏会保留当前打开的标签页，因此书签或重新加载会打开同一个标签页。您可以使用方向键以及 **Home** 和 **End** 在标签页之间移动。在手机等窄屏幕上，每个表格行会显示为一张卡片。

### 数据有多新

部署的每位用户共享来自 AWS 的相同答案。每个数据块都会显示 AWS 作出回答的时间，例如 `刚刚更新` 或 `更新于 3分钟前`。将鼠标悬停在该标签上可查看确切时间。

- 打开某个标签页，或在切换到别处后回到页面时，屏幕上超过其缓存时间的数据会重新加载。您无需重新加载页面。
- Spot 分数按计划更新，而不是在您打开页面时更新。请参阅 [Spot 分数如何更新](#spot-分数如何更新)。
- **刷新** 会立即再向 AWS 查询。由于答案是共享的，部署对同一条目最多每分钟向 AWS 查询一次。如果有人在不到一分钟前刷新过，您会看到该次的答案和一条提示：`此数据不到一分钟前刚刷新过，因此您看到的是该次的结果。您可以在 N 秒后再次刷新。`
- 在新数据到达之前，旧数据会保留在屏幕上。

### 编辑实例列表

默认情况下，**实例类型** 列表会显示每个提供的 GPU 类型，按自然顺序排列并按系列分组。要只保留您关注的类型，请选择 **编辑实例列表**，取消勾选您不需要的类型，然后选择 **保存**。自定义列表最多可包含 20 个类型，并且至少要保留一个。页面只在此浏览器中保存实例列表；它不会跟随您到其他浏览器或设备。要恢复显示每个提供的类型，请打开该对话框，选择 **全选**，然后选择 **保存**。

## Spot 分数标签页

此标签页回答：“哪些区域可能满足我所需 GPU 的 Spot 请求？”

### 阅读表格

表格中每个区域一行，每个**分数组**一列。分数组是一个实例系列加一个 GPU 数量，例如 `g6e · 4 个 GPU`。将鼠标悬停在列标题上、用键盘将焦点移到列标题，或点按列标题，可查看该组中的规格；如果已知价格，还会列出每个规格在表格中各区域的最低 Spot 价格。按 Escape 可关闭。单元格显示该区域对该组的 Spot 放置分数，范围为 1 到 10。不销售任何所显示分数组的区域会折叠为表格下方的一行，例如 `3 个区域不在所显示的任何分数组中`；选择它可列出这些区域。

分数回答的是一个灵活的问题：以该组任一列出规格发出的 Spot 请求，在该区域中被满足的可能性有多大？它不是单个规格的分数。要确认某个规格，请为该规格运行测试启动。

| 单元格 | 含义 |
|---|---|
| 有颜色，只有数字 | 该区域至少销售该组的一个规格。颜色代表区域级分数：机会较高（`7 到 10`）、机会中等（`4 到 6`）或机会较低（`1 到 3`）。 |
| `–` | 尚未获得分数。该区域销售某个规格，但会在下一次每日更新时加入该组；或者其第一个分数会在下一次刷新（每 15 分钟）时到达；或者其请求正在等待部署的每日预算出现空间；或者 AWS 暂时停止了新请求。 |
| `•` | 该区域属于该组，但 AWS 没有返回它的 Spot 分数（`有提供，AWS 未提供分数`），或者分数未能加载。AWS 的答案可能不包含某个区域，且不会显示错误。您仍可在该区域运行测试启动。 |
| 空白 | 该区域不销售该组。 |

单元格本身只包含数字或标记。详细信息在悬停文字以及屏幕阅读器读出的标签中，例如 `下次每日更新（HH:MM 本地时间）后获得 Spot 分数`，并附有规格和最低 Spot 价格。该价格显示为 `$x/小时起`，指最便宜的规格在其最便宜的可用区中的价格，工具提示中还会列出每个规格的价格。区域详情标签块（见下文）显示相同的价格。

表格只显示管理员为 Spot 分数选择的系列。其他 GPU 系列仍会出现在供应、价格、配额、测试启动和 Capacity Block 中，但没有分数列。

### 表格、地图和系列

- 标签页顶部的 **表格** 和 **地图** 用于切换视图。地图把每个已启用的区域显示为一个带有其代码的点，颜色表示所显示组中最高的 Spot 分数。选择一个点可打开区域详情。要分开圆点重叠的区域，请使用地图上方的 **+** 和 **−** 放大，或按住 Ctrl 或 Cmd 并滚动鼠标滚轮；拖动可移动放大后的地图，选择 **重置缩放** 可再次查看整个世界。缩放时圆点和标签保持相同大小。页面中没有坐标的区域会列在地图下方。
- **系列** 用于筛选列。打开列表勾选您需要的系列，或在一个都没有勾选时选择 **选择所有系列**。

### 区域详情

在表格中选择一个区域，或在地图上选择一个点，即可打开其详情面板 `{region}：Spot 分数与 GPU 类型`。它包含两个标签块列表：

- **Spot 分数组**：该区域的各分数组，每个都附有其分数和最低 Spot 价格。
- **此处提供的其他 GPU 类型（无 Spot 分数）**：没有分数列的系列中的类型。

选择一个标签块，会显示针对该组或类型的三个按钮：**测试启动**、**检查按需和 Spot** 和 **搜索 Capacity Block**。每个按钮都会跳转到执行该工作的标签页，并已选好区域和类型。**测试启动** 会打开 **按需与 Spot** 标签页上的测试启动面板。

方案表示 EC2 在该区域销售该类型，并不表示有空闲容量。

### Spot 分数如何更新

Spot 分数按计划更新，标签会显示数据的时间，例如 `更新于 12分钟前`。

- **每 15 分钟**，部署会再次向 AWS 查询它已经在请求的分数，并为大家保存答案。
- **每天一次，在 00:30 UTC**，部署会更新各分数组：加入新规格、新区域以及管理员新增的系列，并移除管理员排除的区域。您昨天启用的区域在那之前会显示 `下次每日更新后获得 Spot 分数`。
- **刷新** 会重复部署已在使用的请求，每个组最多每分钟一次。它不会创建新请求，也不会更改组。

AWS 会限制一个账户每天可发出的不同 Spot 分数请求数量，因此新的组、区域或规格可能需要等到下一次每日更新，或等到预算出现空间。

### 如何使用 Spot 放置分数

Spot 放置分数是 AWS 对类似请求在那一刻成功可能性的估计。它会在几分钟内发生变化。标签页顶部的介绍对此作了简要说明：分数是 AWS 的估计（1 到 10），代表此刻在该区域中，以组内任一规格请求一个 Spot 实例能被满足的机会。高分也不一定能启动，而测试启动才是确认某个规格的方法。

五条规则：

1. **进行比较，不要只看数字本身。** 先尝试较高的分数，并用分数对区域和组进行相互排序。
2. **高分不代表一定能启动，低分也仍有可能启动。**
3. **组分数描述的是整个组。** 它表示某个列出的规格可能被满足，但不说明是哪一个。请用测试启动确认某个规格。
4. **查看分数的时间。** 页面会显示 `更新于 N分钟前`。
5. **测试启动才是真正的检查。** 结果会显示 EC2 选择的可用区和规格，以及各用户最近 24 小时的结果。请参阅[运行测试启动](#运行测试启动)。

该分数不是 Spot 容量的库存清单，也不代表按需或 Capacity Block 的可用性。

## 按需与 Spot 标签页

此标签页显示一个区域中的一个实例类型。在标签页页眉中选择 **区域** 和 **实例类型**，并使用 **编辑实例列表** 缩短类型列表。页面从您上次使用的选择开始，Spot 分数区域详情中的 **检查按需和 Spot** 按钮也会跳转到这里。此标签页从上到下包含以下部分：

- **按需定价**：一行类似 `按需定价：每小时 $x` 的文字，附有该价格的时间。它是该区域 Linux 的公开定价。当 Price List 中没有匹配项时，显示为 `无法获取`。
- **各区域的 Spot 分数**：该类型所属分数组在每个区域中的分数；当该系列在您的部署中不获取 Spot 分数时，会附有说明。
- **测试启动**：向 EC2 请求一个实例的面板。请参阅[运行测试启动](#运行测试启动)。
- **可用区**：一张包含每个可用区 Spot 价格的表格。请参阅[可用区价格与使用 CLI 预留](#可用区价格与使用-cli-预留)。

### 运行测试启动

测试启动会向 EC2 请求一个实例，并在启动调用之后立即终止它。它告诉您那一刻是否存在容量。

1. 在 **按需与 Spot** 标签页的测试启动面板中，使用该标签页的 **区域** 列表选择区域，然后在 **测试对象** 下选择一个分数组。您也可以选择该组中的一个规格。
2. 选择市场：按需或 Spot。如果管理员关闭了 Spot 测试启动，就没有 Spot 选项。
3. 选择 **测试启动**。对话框会显示组或规格以及市场。按需测试会启动一个实例并立即终止，并按该实例类型的最短计费时长产生费用。Spot 测试会请求一个 Spot 实例并立即终止，可能会产生少量费用。选择 **启动并终止**，或选择 **取消**。
4. 按钮会显示 `正在测试...`，然后显示结果，包括 EC2 选择的可用区和规格，或找不到容量的原因。

启动的工作方式：页面会在该区域的各个默认子网（每个可用区一个）以及该组中符合您 vCPU 配额的各个规格范围内，向 EC2 请求一个实例。由 EC2 选择其中一个。对于 Spot，请求使用 `price-capacity-optimized` 策略，该策略偏向有容量且价格较低的容量池。对于按需，它使用 `lowest-price` 策略。如果该组中没有任何规格符合您的配额，页面会说明您的配额可用量不足、未启动任何实例，并且不会发出启动调用。

测试启动会进入该区域的默认虚拟私有云（VPC），不分配公有 IP 地址，并使用一个没有入站规则的安全组。它使用与该类型架构相符的 Amazon Linux 2023 映像。按需测试不会启动到开放式 Capacity Reservation 中，因此它衡量的是空闲容量。您无法连接或使用测试实例。每次测试启动还会附带一个很小的启动脚本，在 5 分钟后关闭实例电源；由于启动设置为关机时终止，实例随后会自行终止。这是一项兜底措施；成功的测试启动通常会被立即终止。

如果该区域没有默认 VPC，测试启动会关闭，并显示消息 `此区域没有默认 VPC`。请联系管理员。

**限制。** 管理员会设置三项限制，页面会显示您的计数：

- **冷却时间**（默认 15 分钟）。对相同组或规格、市场和区域的重复测试会返回先前的结果，而不会再次启动。
- **每用户每日上限**（`maxTestLaunchesPerUserPerDay`，默认 50）。它在 00:00 UTC 重置，而不是在您第一次测试的 24 小时之后。
- **全部署每日上限**（`maxTestLaunchesPerDay`，默认 100），由各用户共用。页面会显示 `今天的测试启动：N/M（所有用户）` 以及您自己的计数。

到达 EC2 的测试会计入，包括被 EC2 拒绝的测试，例如因为无容量或配额上限。没有明确结果就结束的测试也会计入。以下情况不计入：冷却期内的缓存结果、表示另一项测试正在运行的答案、被服务或 EC2 限流的请求（页面显示 `同时发出的请求过多...`，或显示 `错误` 并附有 `RequestLimitExceeded`）、服务器剩余时间不足以启动的请求，以及在启动调用之前失败的请求（例如配额可用量不足，或 `此区域没有默认 VPC`）。

在面板下方，页面会列出该区域最近 24 小时的**观察结果**：针对每个组和市场，有多少次测试已启动、无容量、遇到配额或失败，以及 EC2 选择的可用区和规格。这些计数包括部署的每位用户，但不包含用户名。

### 如何解读测试启动结果

| 结果 | 含义 | 下一步 |
|---|---|---|
| `已启动` | EC2 启动了实例，因此那一刻该组或规格以及市场存在容量。页面会显示 EC2 选择的可用区和规格，并在启动调用之后立即终止该实例。 | 尽快启动您自己的实例。几分钟后容量可能就会消失。如果您需要容量保持可用，可以考虑 Capacity Block。 |
| `无容量` | EC2 针对它尝试的规格和可用区返回了容量错误，例如 `InsufficientInstanceCapacity`。 | 尝试另一个分数较高的区域、另一个组，或 Capacity Block。连续多次 `无容量` 的结果比单次结果是更强的信号。 |
| `配额上限` | 某项限制阻止了启动，例如 `VcpuLimitExceeded`。这并不是容量不足。 | 打开 **配额** 标签页。请参阅[场景 3](#场景-3我遇到了配额错误)。 |
| `不支持` | EC2 为此请求返回了 `Unsupported` 错误代码。 | 尝试另一个市场或另一个组。 |
| `错误` | EC2 返回了其他错误。结果会显示 EC2 的原因和错误代码。当代码为 `RequestLimitExceeded` 时，表示 EC2 限流了该请求：没有启动任何实例，该测试也不计入；请稍后再测试。 | 阅读错误代码。如果反复出现，请联系管理员。 |
| `测试启动结束时没有明确结果。...` | 示例无法确认 EC2 是否启动了实例，例如因为 EC2 没有及时响应。在时间允许时，示例会查找带有此测试启动标签的实例，并要求 EC2 终止找到的实例。计划的清理和实例的自行关机会处理其余情况。由于请求可能已到达 EC2，今天的计数已保留。 | 等到冷却时间结束（`testLaunchCooldownMinutes`，默认 15 分钟）后再次测试。在此之前，页面会显示此结果。如果反复出现，请联系管理员。 |
| `服务器出现问题。请重试。` | 服务器剩余的时间不足以安全地开始测试启动。没有启动任何实例，今天的计数已退回。 | 再次选择 **测试启动**。 |
| `同时发出的请求过多。请稍等片刻，然后选择“刷新”。` | 在测试开始之前，服务限流了该请求。没有启动任何实例，该请求也不计入。 | 稍等片刻，然后选择 **刷新** 并再次测试。 |
| `此区域中正在运行相同选择和市场的另一项测试。请稍后重试。` | 另一位用户发起了相同的测试。页面不会启动第二个实例。 | 稍等片刻，然后选择 **刷新**。 |
| `这是 N 分钟前的结果：...` | 冷却时间内已经对相同目标、市场和区域运行过测试，因此页面显示该次先前的结果。这在部署的各用户之间通用。 | 等到冷却时间结束以获得新的答案。 |

### 可用区价格与使用 CLI 预留

**可用区** 表格中，每个提供该类型的可用区占一行，共三列：**可用区**、**Spot 价格 / 小时**，以及 **使用 CLI 预留** 按钮。Spot 价格是该可用区 Linux 的最新 Spot 市场价格，括号中是它占按需定价的比例，例如 `（为按需的 40%）`。价格经常变动，因此您实际支付的价格可能不同。标题旁信息按钮的悬停文字对此作了说明。

**使用 CLI 预留** 会打开一个对话框，其中有针对该可用区和类型的 `aws ec2 create-capacity-reservation` 命令。该命令请求一个实例，并将结束日期设为您打开对话框起一小时后。选择复制该命令，然后用您自己的凭证自行执行。页面不会创建该预留。对话框会提醒您：Capacity Reservation 从创建的那一刻起，就会以按需费率计费，直到它结束或您取消为止。如果您不再需要它，请在 EC2 控制台中取消。

## Capacity Block 标签页

适用于 ML（机器学习）的 Capacity Block 会在一个可用区中预留 GPU 实例，时长为固定天数，从未来的某个日期开始。此标签页有自己的区域和类型选择；您第一次打开它时，这些选择从您上次使用的区域和类型开始。它有两个子标签页。使用方向键在它们之间移动。

### 搜索可用性

| 控件 | 含义 |
|---|---|
| **区域** | 要搜索的区域。打开列表勾选区域，或使用 **全选** 和 **清除**。 |
| **实例类型** | 要搜索的实例类型。列表只包含在所选区域中支持 Capacity Block 的类型；`（3 个区域中的 2 个）` 之类的标签表示所选区域中只有部分区域提供该类型。 |
| **实例数量** | Capacity Block 包含的实例数，1 到 64。 |
| **时长（天）** | Capacity Block 的持续时间：1 到 14 天，之后按 7 天递增，最多 182 天，与 EC2 文档所列一致。 |
| **最早开始日（选填，UTC 日）** | 留空可查看最早的方案。选择一个日期（最多为今天（UTC）起 14 天），可查看在该日 UTC 开始时间当天或之后开始的方案。 |
| **查找 EC2 Capacity Block** | 运行搜索。在表单填写完整之前，它保持不可用，并在旁边显示原因。 |
| **创建到货提醒** | 从同一个表单添加 Capacity Block 提醒。仅在管理员开启电子邮件提醒时显示。 |

**重新搜索** 会按当时的选择再次运行您上一次的搜索。方案不会被缓存：每次搜索都会查询 EC2。

搜索会检查 EC2 提供的每个区域与类型组合，最多同时六个，并显示带有 `已搜索 N / M` 的进度条。如果服务繁忙并限流了某个组合，页面会在其他组合完成后再尝试该组合一次。一次搜索最多涵盖 40 个组合。结果行会随着答案到达而出现，并按最早开始时间排序：

| 列 | 含义 |
|---|---|
| **区域**、**可用区** | Capacity Block 所在的位置。 |
| **实例类型**、**实例** | Capacity Block 包含的内容。 |
| **开始**、**结束** | Capacity Block 开始和结束的时间，以您浏览器的时区显示。 |
| **时长** | Capacity Block 的长度，例如 `1 天` 或 `14 天`。 |
| **预付费用** | EC2 为该方案返回的费用，使用其货币。`未列出` 表示 EC2 没有返回费用。 |
| **每实例小时** | 预付费用除以 Capacity Block 的小时数和实例数，用于比较不同规模的方案。 |
| **购买** | **在 EC2 控制台中购买** 会在新标签页中打开该行所在区域的 EC2 控制台 Capacity Reservation 页面，您在那里购买 Capacity Block。 |

此页面不会购买任何内容。请在 EC2 控制台中购买。其他客户可能在您行动之前购买该方案，因此请在购买前再次检查。费用是 EC2 为该方案列出的金额；您实际支付的金额可能不同，例如因税费。

所选组合中，如果该区域的列表未列出该类型可用于 Capacity Block，该组合就不会被搜索；它会在进度条下方显示一次，例如 `p4d.24xlarge：ap-northeast-1不以 Capacity Block 形式提供`。如果页面无法加载某个区域的列表，就会搜索该区域的组合，并显示 EC2 的答复。被 EC2 拒绝的组合会在进度条下方显示一行，例如 `p5.4xlarge：不支持 Capacity Block（us-east-1）`，或说明 EC2 目前不接受该类型的时长或数量。当搜索没有找到任何结果时，表格会显示 `没有匹配的 Capacity Block。请尝试减少实例数量、更换时长或增加区域。`，并附有 **可用时提醒我** 链接。

表单上方的 **最近的搜索** 以标签块的形式显示您最近五次搜索，只保存在此浏览器中。**创建到货提醒** 会打开一个对话框，显示区域与类型组合的数量、实例数量和时长，然后为每个组合添加一个提醒。它会跳过您已有的提醒，并在达到您的提醒上限时停止。

### 最大容量

选择 **区域**、**实例类型** 和 **时长（天）**，然后选择 **查找最大容量**。页面会找出有方案的最大实例数量（1 到 64），并显示该数量的最早开始时间、结束时间、可用区和预付费用。页面最多发送三个缩小范围的请求，因此大约需要 10 到 20 秒才能得到答案。`当前没有可用容量` 表示对于 1 到 64 的数量，EC2 没有列出该时长的 Capacity Block。请尝试更短的时长或其他区域，或在 **搜索可用性** 中创建到货提醒。

## 配额标签页

**配额** 标签页显示其页眉中所选区域的配额：P、G 和 VT、Trn 以及 Inf 实例系列的按需和 Spot vCPU 配额，以及每个系列的 Capacity Block 配额。每个组都有自己的表格和简短说明。如果您以前使用过某个实例类型，适用于其系列的配额会在每个组中排在最前并突出显示。将鼠标移到配额名称上、用键盘聚焦它或点按它，会显示一条提示，说明用量统计的内容。按 Esc 可关闭提示。

| 列 | 含义 |
|---|---|
| **配额** | Service Quotas 报告的配额名称。`不可调整` 标记表示您无法申请提高配额。Capacity Block 行带有 `仅上限` 标签。 |
| **上限** | 带单位的配额值，例如 `192 个 vCPU`。`AWS 默认值` 标记表示 Service Quotas 没有为您的账户返回已应用的值，因此页面显示 AWS 默认值。 |
| **最近一小时已使用（此账户）** | 仅限按需和 Spot 行。部署本示例的 AWS 账户在最近一小时内的最高用量，来自 Amazon CloudWatch 用量指标，并附有进度条和占上限的比例。达到 80% 时，进度条变为黄色，单元格显示 `接近上限`；达到 100% 时变为红色，并显示 `超出上限`。 |
| **链接** | **在 Service Quotas 中查看** 会在新标签页中打开 Service Quotas 控制台中该区域的此项配额。 |

当某个配额达到或超出上限时，表格上方的提示会说明：需要更多该配额的启动会失败，直到用量下降或上限提高。AWS 不发布 Capacity Block 配额的用量指标，因此它们的表格只显示上限。用量指标可能比实际使用滞后几分钟。**刷新** 会再次查询 Service Quotas 和 CloudWatch。此标签页一次检查一个区域，并且是只读的。要申请提高配额，请使用 **在 Service Quotas 中查看** 链接。

## 提醒标签页

此标签页在管理员开启电子邮件提醒时显示。当某个信号从不可用变为可用时，提醒会向您发送电子邮件。提醒只读取信号；它们不会运行测试启动，也不会预留任何内容。

1. 在表单中选择一个 **区域**。它从您上次使用的选择开始。
2. 选择一个 **信号**：
   - **Capacity Block 方案**、**天数**，以及 1 到 64 之间的 **实例数量**。当 EC2 列出符合该数量和时长的 Capacity Block 方案时，提醒会变为可用。
   - **Spot 放置分数** 和 **分数不低于**（1 到 10）。下一个列表会变为 **分数组**：选择该区域销售的一个组，例如 `g6e · 4 个 GPU`。当该组的区域分数达到您的阈值时，提醒会变为可用。它涵盖管理员为 Spot 分数选择的系列，并跟随每 15 分钟一次的刷新。
3. 对于 Capacity Block 提醒，请选择一个 **实例类型**。选择 **添加提醒**。要同时为多个区域和类型添加 Capacity Block 提醒，请使用 **Capacity Block** 标签页上的 **创建到货提醒**。
4. 添加第一个提醒时，一条黄色提示会请您确认订阅。打开来自 AWS Notifications 的电子邮件，选择 **Confirm subscription**。您只需确认一次。电子邮件会发送到您用户的地址。

在您确认之前，您不会收到任何提醒邮件。提醒会保留其状态，因此如果在您确认后的第一次检查时信号仍然可用，邮件会在那时发出。Amazon Simple Notification Service（Amazon SNS）会删除 48 小时内仍未确认的订阅。如果发生这种情况，请删除您的提醒并重新添加，以获得新的确认邮件。

| 列 | 含义 |
|---|---|
| **区域**、**实例类型** | 提醒检查的对象。对于 Spot 分数提醒，**实例类型** 列显示分数组。 |
| **信号** | `Capacity Block，N 个实例，N 天` 或 `Spot 分数不低于 N`。 |
| **状态** | `等待首次检查`、`不可用`、`当前可用`，或附有原因的 `EC2 不接受此提醒（...）`，例如 EC2 不为该类型提供该时长或实例数量时。被拒绝的提醒不会发送邮件；请删除它，并添加一个 EC2 接受的提醒。 |
| **上次检查** | 上一次检查运行的时间距今多久，或 `尚未检查`。 |
| **删除** | 在确认对话框之后移除该提醒。 |

标签页顶部的说明以管理员设置的检查间隔开头，例如 `每 15 分钟检查一次提醒。`。检查按计划运行，因此在两次检查之间出现又消失的信号不会发送邮件。提醒发送邮件之后，只有在信号先变为不可用、再变为可用时，才会再次发送。当您删除最后一个提醒时，页面也会移除您的电子邮件订阅。要停止向您的地址发送提醒邮件，请选择提醒邮件中的取消订阅链接。

## 用户标签页

**用户** 标签页只是一份指南：它不调用任何 API，也不显示用户数据。它说明如何在 Amazon Cognito 控制台中添加、更新和删除用户，用户就是在那里管理的。选择 **打开 Amazon Cognito 控制台**，可在新标签页中打开此部署的用户池。这需要具备打开该用户池的 AWS 权限；如果您没有这些权限，请联系管理员。普通用户不需要此标签页。

## 决策手册

### 场景 1：需要预留容量的多周训练任务

您需要某个类型的多个实例，为期三周，并且在任务开始时容量必须到位。

1. 在 **Capacity Block** 中，勾选您可以使用的区域和类型，将 **时长（天）** 设为 `21`，将 **实例数量** 设为您需要的数量，然后选择 **查找 EC2 Capacity Block**。在 **配额** 中检查 Capacity Block 配额是否足够。
2. 比较 **开始**、**每实例小时** 和可用区，然后在合适的行上选择 **在 EC2 控制台中购买**。请尽快购买；方案可能被其他客户买走。
3. 如果没有匹配的结果，请针对一个区域尝试 **最大容量**，尝试相近的时长，例如 `14` 或 `28`，或选择 **可用时提醒我**。收到邮件后，选择 **重新搜索** 或最近搜索的标签块。

### 场景 2：灵活的 Spot 批处理作业

您的作业可以在一系列区域和可用区中运行，并且可以停止和重新启动。

1. 在 **Spot 分数** 中，找到您所需 GPU 组的列，并查找分数较高（`7 到 10`）的区域。比较工具提示和区域详情中的 Spot 价格。在 **配额** 中检查该区域的 Spot 配额是否有可用量。
2. 在最佳区域的区域详情中选择 **测试启动**（它会打开 **按需与 Spot** 标签页），选择组（或一个规格），选择 Spot，然后运行测试启动。结果会告诉您 EC2 选择的可用区和规格。
3. 如果没有区域的分数足够高，请在 **提醒** 标签页上添加一个 **Spot 放置分数** 提醒，并使用您可接受的阈值，例如 `7`。

### 场景 3：我遇到了配额错误

测试启动或您自己的启动返回了 `配额上限` 或 `VcpuLimitExceeded` 之类的错误，或者页面提示您的配额可用量不足。

1. 针对发生问题的区域打开 **配额**。您上次使用的类型所对应的配额会在每个组中排在最前。
2. 比较 **最近一小时已使用（此账户）** 和 **上限**。`接近上限` 或 `超出上限` 表示余量很少或没有余量。有效的 Capacity Reservation 会计入按需配额。
3. 在页眉中选择另一个区域以寻找余量，或选择 **在 Service Quotas 中查看** 申请提高配额。`不可调整` 的配额无法提高。用量可能滞后几分钟；结束实例后请选择 **刷新**。

## 成本与安全说明

- 测试启动会启动一个真实实例几秒钟，然后终止它。按需测试按该实例类型的最短计费时长计费。Spot 测试也可能产生费用。请对最大的实例类型谨慎测试。
- 冷却时间把每个组或规格、市场和区域在时间窗口内限制为一次启动，跨用户生效。每日上限限制您的用量和整个部署的用量。
- 页面显示的是定价和最新的 Spot 价格。您实际支付的金额可能不同，例如因折扣、Savings Plans 或税费。
- 您在 EC2 控制台中购买的 Capacity Block 是一次购买。您通过 **使用 CLI 预留** 复制的命令会创建一个 Capacity Reservation，从创建起以按需费率计费，直到它结束或您取消为止。页面不会跟踪或取消其中任何一项。
- 每个答案都只反映某一时间点。`已启动` 结果或某个方案不会预留任何内容，而 Spot 放置分数表示的是可能性。

| 身份验证器代码被拒绝 | 检查手机上的时间是否设为自动设置。在代码变化之前输入当前代码。如果您丢失了设备，请联系管理员。 |
| 忘记密码 | 在登录页面上选择 **Forgot your password?**，并使用发送到您电子邮件地址的验证码。 |
| 页面显示 `请登录后继续。` | 选择 **登录**。 |
| `无法加载页面。` | 页面无法访问 API。选择 **重试**。如果反复出现，请联系管理员。 |
| 长时间闲置后页面将您转到登录页面，或某项操作失败并显示 `您的会话已过期。` | 您的会话已结束。默认情况下会话最长持续 12 小时，关闭浏览器标签页也会结束会话。请重新登录，然后重复该操作；过期的请求没有到达 API 函数，因此没有启动任何内容。 |
| 带有 **重试** 的红色消息 | 标签页的这一部分未能加载。选择 **重试**。消息会指出是哪一部分并给出原因。 |
| 页面显示 `正在为此部署设置 Spot 分数` 或提示正在建立分数组 | 首次部署之后，或管理员更改了 Spot 分数系列之后，部署会在第一个请求时建立分数组，约需一分钟。标签页保持打开时，页面每分钟会再次读取分数组并自动更新。 |
| 表格显示 `此部署没有 Spot 分数组` | 分数组已建立，但为 Spot 分数选择的系列在已启用的区域中均不提供。请让管理员检查 `spotScoreFamilies`。 |
| 单元格显示 `下次每日更新后获得 Spot 分数` | 该区域销售该组的某个规格，但会在下一次每日更新（00:30 UTC，以您的本地时间显示）时加入该组。无需任何操作。单元格显示 `–`，悬停时会出现该文字。 |

| Spot 分数很高，但测试启动失败 | 这是正常的。分数是对那一刻的估计，等您启动时容量可能已经消失。请重试，或尝试另一个区域。请参阅[如何使用 Spot 放置分数](#如何使用-spot-放置分数)。 |

## 术语表

| 术语 | 含义 |
|---|---|
| Capacity Block | 适用于 ML 的 Capacity Block：您购买的固定时段的 GPU 实例，时长从 1 天到 182 天，在一个可用区中从未来的某个日期开始。 |
| 分数组 | 一个实例系列加一个 GPU 数量，例如 `g6e · 4 个 GPU`。组的 Spot 分数是以任一列出规格发出的 Spot 请求被满足的区域级机会。 |
| Spot 放置分数 | EC2 为一个区域返回的 1 到 10 分。分数越高，表示 Spot 请求越可能成功。它表示可能性，而不是承诺。 |
| 每日更新 | 在 00:30 UTC 进行的运行，向 Spot 分数组中加入新规格、新区域和新组。 |
| 定价 | AWS 发布的公开价格，未计入折扣、Savings Plans 或税费。 |
| 配额 | 对您的账户在一个区域中可使用的资源量的限制，例如运行中 P 实例的 vCPU 数。即使存在容量，配额也可能阻止启动。 |
| 测试启动 | 启动一个实例，并由页面在启动调用之后立即终止，以了解那一刻是否存在容量。管理员指南和 API 称之为启动探测。 |
| 冷却时间 | 在这段分钟数内，对相同组或规格、市场和区域的重复测试会返回先前的结果。 |
