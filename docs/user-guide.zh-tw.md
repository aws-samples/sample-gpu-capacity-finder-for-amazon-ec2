# GPU Capacity Finder 使用者指南

> 本文件是[英文版使用者指南](user-guide.md)的直譯，未增減任何內容。如有出入，以英文版為準。

如果您登入 GPU Capacity Finder，在 Amazon Elastic Compute Cloud（Amazon EC2）上尋找圖形處理器（GPU）容量，這份指南就是為您撰寫的。部署此頁面的人另有一份[管理員指南](admin-guide.zh-tw.md)。

## 此工具回答的問題

GPU Capacity Finder 回答一個問題：現在或近期，您可以在哪裡、以什麼方式取得所需的 GPU 執行個體？它讀取您的帳戶已啟用之區域（扣除管理員排除的區域）與各 GPU 執行個體系列的容量訊號，並讓您以一次測試啟動來確認某個訊號。它不管理執行個體、不預留容量，也不啟動您的工作負載：當您決定採取行動時，您可以在 EC2 主控台中購買 Capacity Block，並在 EC2 主控台中預留容量，或使用頁面提供給您複製的 AWS Command Line Interface（AWS CLI）命令預留。

頁面有六個索引標籤，每個對應一項工作，依序為：

- **Spot 分數**依每個 GPU 群組的 Spot 放置分數比較各區域，以表格或地圖呈現。
- **隨需與 Spot**顯示一個區域中的一種執行個體類型：隨需定價、Spot 分數、測試啟動面板，以及每個可用區域的 Spot 價格，並附上預留容量的命令。
- **Capacity Block**同時在多個區域和執行個體類型中搜尋您可以購買的 Capacity Block 方案，並找出目前提供的最大執行個體數量。
- **配額**顯示您的服務配額及其各自的使用量，因為在容量成為問題之前，配額就可能阻擋啟動。
- **提醒**列出您的電子郵件提醒。只有在管理員開啟電子郵件提醒時才會出現。
- **使用者**說明如何在 Amazon Cognito 主控台中新增、更新和刪除使用者。一般使用者不需要它。

每個結果都是特定時間點的結果：它描述的是檢查當下，而不是未來。

## 登入與首次設定

您的管理員會建立您的使用者。自助註冊已關閉。

1. 找到一封含有您的使用者名稱和臨時密碼的電子郵件。臨時密碼會在七天後過期。如果已過期，請管理員寄送新的密碼。
2. 開啟管理員提供給您的網站 URL，然後選擇**登入**。頁面會將您帶到 Amazon Cognito 登入頁面。
3. 以您的電子郵件地址和臨時密碼登入。
4. 設定新密碼。密碼至少需要 12 個字元，並包含一個大寫字母、一個小寫字母、一個數字和一個符號。
5. 設定多重要素驗證（MFA）。登入頁面會顯示一個 QR 碼。請以支援以時間為基礎之一次性密碼（TOTP）的驗證器應用程式掃描它，然後輸入應用程式中的六位數驗證碼。本範例只接受驗證器應用程式，不接受簡訊。
6. 頁面會開啟在第一個索引標籤。

之後每次登入時，請輸入您的密碼和驗證器應用程式中目前的驗證碼。如果您忘記密碼，請在登入頁面選擇 **Forgot your password?**；驗證碼會寄到您的電子郵件地址。

您的工作階段預設最長為 12 小時；長度由管理員設定。只要索引標籤保持開啟，頁面就會在背景更新您的登入。頁面只為目前的瀏覽器索引標籤保留您的登入，因此關閉索引標籤就會登出。選擇右上角的**登出**即可結束工作階段。

頁首有語言切換器，可切換英文、繁體中文和簡體中文。頁面會在此瀏覽器中記住您的選擇，而網址中的 `?lang=en-US`、`?lang=zh-TW` 或 `?lang=zh-CN` 會選擇語言。

## 頁面總覽

每個索引標籤的頁首都有自己的控制項，例如**區域**清單。頁面會在此瀏覽器中記住您上次使用的區域和執行個體類型，並將它們作為其他索引標籤的初始選擇。

索引標籤會在您第一次開啟時載入資料，並在您變更其選擇時再次載入。請求執行期間，頂端列下方會顯示一條細細的橘色進度列。啟動動作的按鈕會顯示旋轉圖示和 `測試中...` 之類的文字，直到動作完成。請求失敗時，原本顯示資料的位置會出現紅色訊息，並附有**重試**按鈕。只有索引標籤的一部分失敗時，訊息會指出是哪個部分，索引標籤的其餘部分仍會顯示。網址列會保留開啟的索引標籤，因此書籤或重新載入會開啟同一個索引標籤。您可以使用方向鍵，以及 **Home** 和 **End** 鍵在索引標籤之間移動。在手機等窄螢幕上，每個表格列會以卡片顯示。

### 資料的新鮮度

部署的每位使用者共用來自 AWS 的相同結果。每個資料區塊都會顯示 AWS 回應的時間，例如 `剛剛更新` 或 `更新於 3 分鐘前`。將游標停在標籤上即可查看確切時間。

- 開啟索引標籤，或在切換到別處之後回到頁面時，畫面上超過快取時間的資料會重新載入。您不需要重新載入頁面。
- Spot 分數依排程更新，而不是在您開啟頁面時更新。請參閱 [Spot 分數如何更新](#spot-分數如何更新)。
- **重新整理**會立即再向 AWS 查詢。由於結果是共用的，部署對同一個項目每分鐘最多只會再向 AWS 查詢一次。如果有人在不到一分鐘前重新整理過，您會看到該次的結果和一則說明：`此資料不到一分鐘前剛重新整理過，因此您看到的是該次的結果。您可以在 N 秒後再次重新整理。`
- 在新資料送達之前，舊資料會保留在畫面上。

### 編輯執行個體清單

根據預設，**執行個體類型**清單會顯示每個有提供的 GPU 類型，依自然順序排列並依系列分組。若只想保留您關心的類型，請選擇**編輯執行個體清單**，取消勾選您不想要的類型，然後選擇**儲存**。自訂清單最多可以有 20 個類型，且您必須至少保留一個。頁面只在此瀏覽器中保留執行個體清單；它不會跟著您到其他瀏覽器或裝置。若要恢復顯示每個有提供的類型，請開啟對話方塊，選擇**全選**，然後選擇**儲存**。

## Spot 分數索引標籤

此索引標籤回答「哪些區域可能滿足我所需 GPU 的 Spot 請求？」。

### 解讀表格

表格中每個區域一列，每個**分數群組**一欄。分數群組是一個執行個體系列搭配一種 GPU 數量，例如 `g6e · 4 個 GPU`。將游標停在欄標題上、以鍵盤將焦點移到欄標題，或點選欄標題，即可查看群組中的尺寸；若已知價格，也會列出每個尺寸在表格中各區域的最低 Spot 價格。按 Escape 即可關閉。儲存格顯示該區域對該群組的 Spot 放置分數，範圍為 1 到 10。未提供任何所顯示分數群組的區域，會收合成表格下方的一行，例如 `3 個區域不在所顯示的任何分數群組中`；選擇它即可列出這些區域。

分數回答一個彈性的問題：在該區域中，針對群組內任一列出尺寸的 Spot 請求被滿足的可能性有多高？它不是單一尺寸的分數。若要確認某個尺寸，請對該尺寸執行測試啟動。

| 儲存格 | 意義 |
|---|---|
| 有顏色，只顯示數字 | 該區域至少提供群組中的一個尺寸。顏色代表區域層級的分數：機會較高（`7 至 10`）、機會中等（`4 至 6`）或機會較低（`1 至 3`）。 |
| `–` | 尚未取得分數。該區域提供某個尺寸，但會在下次每日更新時加入群組；或其第一個分數會在下次重新整理時取得（每 15 分鐘）；或其請求正在等候部署每日預算的額度；或 AWS 暫時停止了新的請求。 |
| `•` | 該區域屬於此群組，但 AWS 沒有傳回它的 Spot 分數（`有提供，AWS 未提供分數`），或分數未載入。AWS 的回應可能不含某個區域，且不會顯示錯誤。您仍可在該區域執行測試啟動。 |
| 空白 | 該區域未提供此群組。 |

儲存格本身只包含數字或符號。詳細資訊在游標停留時的提示文字中，以及螢幕閱讀器朗讀的標籤中，例如 `下次每日更新（HH:MM 當地時間）後取得 Spot 分數`，並附上尺寸和最低的 Spot 價格。該價格顯示為 `$x/小時起`，代表最便宜尺寸在其最便宜可用區域中的價格，提示中也會列出每個尺寸的價格。區域詳細資料的標籤（見下文）會顯示相同的價格。

表格只顯示管理員為 Spot 分數選擇的系列。其他 GPU 系列仍會出現在供應、價格、配額、測試啟動和 Capacity Block 中，但沒有分數欄。

### 表格、地圖與系列

- **表格**和**地圖**（位於索引標籤頂端）會切換檢視。地圖會將每個已啟用的區域以帶有代碼的圓點呈現，顏色依所顯示群組中最高的 Spot 分數而定。選擇圓點即可開啟區域詳細資料。若要分開圓點重疊的區域，請使用地圖上方的 **+** 和 **−** 放大，或按住 Ctrl 或 Cmd 並捲動滑鼠滾輪；拖曳即可移動放大後的地圖，選擇**重設縮放**即可再次查看整個世界。縮放時圓點和標籤會保持相同大小。頁面中沒有座標的區域會列在地圖下方。
- **系列**會篩選欄。開啟清單以勾選您想要的系列，或在未勾選任何系列時選擇**選取所有系列**。

### 區域詳細資料

在表格中選擇一個區域，或在地圖上選擇一個圓點，即可開啟其詳細資料面板 `{region}：Spot 分數與 GPU 類型`。它有兩組標籤：

- **Spot 分數群組**：該區域的分數群組，每個都附有其分數和最低的 Spot 價格。
- **此處提供的其他 GPU 類型（無 Spot 分數）**：屬於沒有分數欄之系列的類型。

選擇一個標籤，即可看到該群組或類型的三個按鈕：**測試啟動**、**查看隨需與 Spot** 和**搜尋 Capacity Block**。每個按鈕都會跳到執行該工作的索引標籤，並已選好區域和類型。**測試啟動**會開啟**隨需與 Spot**索引標籤上的測試啟動面板。

方案表示 EC2 在該區域提供此類型，並不表示有可用的容量。

### Spot 分數如何更新

Spot 分數依排程更新，標籤會顯示其經過時間，例如 `更新於 12 分鐘前`。

- **每 15 分鐘**，部署會針對它已在請求的分數再次向 AWS 查詢，並為每個人儲存結果。
- **每天一次，於 00:30 UTC**，部署會更新群組：加入新尺寸、新區域，以及管理員新增的系列，並移除管理員排除的區域。您昨天啟用的區域在那之前會顯示 `下次每日更新後取得 Spot 分數`。
- **重新整理**會重複部署已在使用的請求，每個群組每分鐘最多一次。它不會建立新請求，也不會變更群組。

AWS 會限制一個帳戶每天可發出的不同 Spot 分數請求數量，因此新的群組、區域或尺寸可能要等到下次每日更新，或等到預算有額度時才會取得分數。

### 如何使用 Spot 放置分數

Spot 放置分數是 AWS 對於與此類似的 Spot 請求在當下成功之可能性的估計。它會在幾分鐘內變化。索引標籤頂端的說明簡短地表達了這一點：分數是 AWS 的估計（1 到 10），代表此刻在該區域中，以群組內任一尺寸請求一個 Spot 執行個體能被滿足的機會。高分不代表必定能啟動，而測試啟動是確認某個尺寸的方法。

五項原則：

1. **用來比較，不要只看數字本身。** 先嘗試分數較高的選項，並用分數來為區域和群組排序。
2. **高分不代表必定能啟動，低分也仍可能啟動。**
3. **群組分數描述的是整個群組。** 它表示某個列出的尺寸可能被滿足，但不會指出是哪一個。請以測試啟動確認某個尺寸。
4. **留意分數的經過時間。** 頁面會顯示 `更新於 N 分鐘前`。
5. **測試啟動才是真正的確認。** 結果會顯示 EC2 挑選的可用區域和尺寸，以及所有使用者過去 24 小時的結果。請參閱[執行測試啟動](#執行測試啟動)。

分數不是 Spot 容量的庫存清單，也不代表隨需或 Capacity Block 的可用性。

## 隨需與 Spot 索引標籤

此索引標籤顯示一個區域中的一種執行個體類型。請在索引標籤頁首選擇**區域**和**執行個體類型**，並使用**編輯執行個體清單**縮短類型清單。頁面會從您上次使用的選擇開始，而 Spot 分數區域詳細資料中的**查看隨需與 Spot**按鈕也會跳到這裡。此索引標籤由上而下包含以下部分：

- **隨需定價**，例如 `隨需定價：每小時 $x` 這樣的一行，並附有價格的經過時間。這是該區域 Linux 的公開定價。當 Price List 沒有相符項目時，會顯示 `無法取得`。
- **各區域的 Spot 分數**：該類型所屬分數群組在每個區域的分數；如果您的部署不為該系列取得 Spot 分數，會附上說明。
- **測試啟動**：向 EC2 請求一個執行個體的面板。請參閱[執行測試啟動](#執行測試啟動)。
- **可用區域**：列出每個可用區域 Spot 價格的表格。請參閱[可用區域價格與使用 CLI 預留](#可用區域價格與使用-cli-預留)。

### 執行測試啟動

測試啟動會向 EC2 請求一個執行個體，並在啟動呼叫之後立即終止它。它會告訴您在那一刻是否有容量。

1. 在**隨需與 Spot**索引標籤的測試啟動面板中，使用索引標籤的**區域**清單選擇區域，然後在**測試對象**下選擇一個分數群組。您也可以選擇群組中的一個尺寸。
2. 選擇市場：隨需或 Spot。當管理員關閉 Spot 測試啟動時，Spot 選項不會出現。
3. 選擇**測試啟動**。對話方塊會顯示群組或尺寸以及市場。隨需測試會啟動一個執行個體並立即終止，並依該執行個體類型的最短計費期間產生費用。Spot 測試會請求一個 Spot 執行個體並立即終止，可能會產生少量費用。選擇**啟動並終止**，或選擇**取消**。
4. 按鈕會顯示 `測試中...`，接著結果會顯示 EC2 挑選的可用區域和尺寸，或它找不到容量的原因。

啟動的運作方式：頁面會向 EC2 請求一個執行個體，範圍涵蓋該區域的每個預設子網路（每個可用區域一個），以及群組中符合您 vCPU 配額的每個尺寸。EC2 會挑選其中一個。對於 Spot，請求使用 `price-capacity-optimized` 策略，偏好有容量且價格低的集區。對於隨需，則使用 `lowest-price` 策略。如果群組中沒有任何尺寸符合您的配額，頁面會說明您的配額可用量太少、未啟動任何執行個體，且不會發出啟動呼叫。

測試會啟動到該區域的預設虛擬私有雲端（VPC）中，沒有公有 IP 位址，並使用沒有傳入規則的安全群組。它使用符合該類型架構的 Amazon Linux 2023 映像。隨需測試不會啟動到開放的 Capacity Reservation 中，因此它測量的是可用容量。您無法連線到測試執行個體，也無法使用它。每次測試啟動還會附帶一個很小的啟動指令碼，在 5 分鐘後關閉執行個體電源，而且由於啟動時設定為關機時終止，執行個體隨後會自行結束。這是一道備援措施；成功的測試啟動通常會立即被終止。

如果該區域沒有預設 VPC，測試啟動會關閉，並顯示訊息 `此區域沒有預設 VPC`。請洽詢您的管理員。

**限制。** 管理員會設定三項限制，頁面會顯示您的計數：

- **冷卻時間**（預設 15 分鐘）。對相同群組或尺寸、市場和區域重複測試時，會傳回先前的結果，而不會再次啟動。
- **每位使用者的每日上限**（`maxTestLaunchesPerUserPerDay`，預設 50）。它會在 00:00 UTC 重設，而不是在您第一次測試的 24 小時後。
- **整個部署的每日上限**（`maxTestLaunchesPerDay`，預設 100），由每位使用者共用。頁面會顯示 `今天的測試啟動：N／M（所有使用者）` 以及您自己的計數。

送達 EC2 的測試會計入，包括被 EC2 拒絕的測試，例如因為沒有容量或配額上限。結束時沒有明確結果的測試也會計入。以下情況不會計入：快取的冷卻時間結果、表示另一項測試正在執行的回應、被服務或 EC2 限流的請求（頁面會顯示 `同時的請求過多...`，或顯示 `錯誤` 並附上 `RequestLimitExceeded`）、伺服器時間不足而無法開始的請求，以及在啟動呼叫之前就失敗的請求（例如配額可用量太少，或 `此區域沒有預設 VPC`）。

面板下方會列出該區域過去 24 小時的**觀察結果**：針對每個群組和市場，有多少次測試已啟動、沒有容量、達到配額上限或失敗，以及 EC2 挑選的可用區域和尺寸。計數包含部署的每位使用者，且不含使用者名稱。

### 如何解讀測試啟動結果

| 結果 | 代表的意義 | 下一步 |
|---|---|---|
| `已啟動` | EC2 已啟動執行個體，因此在那一刻，該群組或尺寸與市場有容量。頁面會顯示 EC2 挑選的可用區域和尺寸，並已在啟動呼叫之後立即將其終止。 | 盡快啟動您自己的執行個體。容量可能在幾分鐘後就消失。如果您需要容量持續存在，請考慮 Capacity Block。 |
| `沒有容量` | EC2 針對它嘗試的尺寸和可用區域傳回容量錯誤，例如 `InsufficientInstanceCapacity`。 | 嘗試另一個高分區域、另一個群組，或 Capacity Block。連續多次 `沒有容量` 的結果，比單次結果更具參考性。 |
| `配額上限` | 某項限制阻擋了啟動，例如 `VcpuLimitExceeded`。這不是容量不足。 | 開啟**配額**索引標籤。請參閱[情境 3](#情境-3我遇到配額錯誤)。 |
| `不支援` | EC2 針對此請求傳回 `Unsupported` 錯誤代碼。 | 嘗試另一個市場或另一個群組。 |
| `錯誤` | EC2 傳回其他錯誤。結果會顯示 EC2 的原因和錯誤代碼。當代碼為 `RequestLimitExceeded` 時，表示 EC2 限流了此請求：沒有啟動任何執行個體，此測試也不會計入；請稍後再測試。 | 閱讀錯誤代碼。如果重複發生，請洽詢您的管理員。 |
| `測試啟動結束時沒有明確結果。...` | 本範例無法確認 EC2 是否啟動了執行個體，例如因為 EC2 未及時回應。在時間允許時，本範例會尋找帶有此測試啟動標籤的執行個體，並要求 EC2 終止找到的任何執行個體。排程清理和執行個體的自行關機會處理其餘情況。由於請求可能已送達 EC2，今天的計數已保留。 | 等到冷卻時間結束（`testLaunchCooldownMinutes`，預設 15 分鐘）後再測試。在那之前，頁面會顯示此結果。如果重複發生，請洽詢您的管理員。 |
| `伺服器發生問題。請再試一次。` | 伺服器剩餘的時間不足以安全地開始測試啟動。沒有啟動任何執行個體，今天的計數也已退回。 | 再次選擇**測試啟動**。 |
| `同時的請求過多。請稍候，然後選擇「重新整理」。` | 服務在測試開始之前限流了此請求。沒有啟動任何執行個體，此請求也不會計入。 | 稍候片刻，然後選擇**重新整理**並再次測試。 |
| `此區域中正在執行相同選擇與市場的另一項測試。請稍後再試。` | 另一位使用者開始了相同的測試。頁面不會啟動第二個執行個體。 | 稍候片刻，然後選擇**重新整理**。 |
| `這是 N 分鐘前的結果：...` | 相同目標、市場和區域的測試在冷卻時間內執行過，因此頁面會顯示先前的結果。這適用於部署的所有使用者。 | 等到冷卻時間結束，以取得新的結果。 |

### 可用區域價格與使用 CLI 預留

**可用區域**表格中，每個提供該類型的可用區域一列，共有三欄：**可用區域**、**Spot 價格 / 小時**，以及**使用 CLI 預留**按鈕。Spot 價格是該可用區域 Linux 的最新 Spot 市場價格，括號中為其相對於隨需定價的比例，例如 `（為隨需的 40%）`。價格經常變動，因此您實際支付的價格可能不同。標題旁資訊按鈕的提示文字會說明這一點。

**使用 CLI 預留**會開啟一個對話方塊，其中有針對該可用區域和類型的 `aws ec2 create-capacity-reservation` 命令。此命令會請求一個執行個體，並將結束時間設定為您開啟對話方塊後的一小時。選擇複製命令，然後以您自己的憑證自行執行。頁面不會建立預留。對話方塊會提醒您，Capacity Reservation 從建立的那一刻起就會依隨需費率計費，直到它結束或您取消為止。如果您不再需要，請在 EC2 主控台中取消它。

## Capacity Block 索引標籤

Capacity Block for ML（機器學習）會在單一可用區域中預留 GPU 執行個體，期間為固定天數，從未來的某個日期開始。此索引標籤有自己的區域和類型選擇；第一次開啟時，會從您上次使用的區域和類型開始。它有兩個子索引標籤。請使用方向鍵在兩者之間移動。

### 搜尋可用性

| 控制項 | 意義 |
|---|---|
| **區域** | 要搜尋的區域。開啟清單以勾選區域，或使用**全選**和**清除**。 |
| **執行個體類型** | 要搜尋的執行個體類型。清單只包含在所選區域中支援 Capacity Block 的類型；`（3 個區域中的 2 個）` 之類的標籤表示只有部分所選區域提供該類型。 |
| **執行個體數量** | Block 包含的執行個體數量，1 到 64。 |
| **期間（天）** | Block 持續的時間：1 到 14 天，之後以 7 天為級距，最多 182 天，依 EC2 文件所列。 |
| **最早開始日（選填，UTC 日）** | 保留空白可查看最早的方案。選擇一個日期（最多為今天（UTC）起 14 天內），可查看在該日 UTC 起始時間當天或之後開始的方案。 |
| **尋找 EC2 Capacity Block** | 執行搜尋。在表單填寫完整之前，它會保持無法使用，並在旁邊顯示原因。 |
| **建立到貨提醒** | 從同一個表單新增 Capacity Block 提醒。僅在管理員開啟電子郵件提醒時顯示。 |

**重新搜尋**會以當時的選擇再次執行您上次的搜尋。方案不會被快取：每次搜尋都會向 EC2 查詢。

搜尋會檢查 EC2 提供的每組區域與類型組合，一次最多六組，並顯示進度列與 `已搜尋 N / M`。如果服務忙碌並限流了某組組合，頁面會在其他組合完成後再嘗試該組一次。一次搜尋最多涵蓋 40 組。結果送達時會逐列出現，依最早開始時間排序：

| 欄 | 意義 |
|---|---|
| **區域**、**可用區域** | Block 所在的位置。 |
| **執行個體類型**、**執行個體** | Block 包含的內容。 |
| **開始**、**結束** | Block 開始和結束的時間，以您瀏覽器的時區顯示。 |
| **期間** | Block 的長度，例如 `1 天` 或 `14 天`。 |
| **預付費用** | EC2 為此方案傳回的費用，以其幣別顯示。`未列出` 表示 EC2 未傳回費用。 |
| **每執行個體小時** | 預付費用除以 Block 的時數和執行個體數量，用來比較不同大小的方案。 |
| **購買** | **在 EC2 主控台購買**會在新索引標籤中開啟該列區域的 EC2 主控台 Capacity Reservation 頁面，您可以在那裡購買 Capacity Block。 |

此頁面不會購買任何項目。請在 EC2 主控台中購買。其他客戶可能在您採取行動之前購買方案，因此請在購買前再次確認。費用是 EC2 為該方案列出的金額；您實際支付的金額可能不同，例如因稅費而異。

所選組合中，若該區域的清單未列出該類型可用於 Capacity Block，該組合就不會搜尋；它會在進度列下方顯示一次，例如 `p4d.24xlarge：ap-northeast-1未以 Capacity Block 形式提供`。如果頁面無法載入某個區域的清單，就會搜尋該區域的組合，並顯示 EC2 的回應。被 EC2 拒絕的組合會在進度列下方顯示一行，例如 `p5.4xlarge：Capacity Block 不支援（us-east-1）`，或說明 EC2 目前不接受該類型的期間或數量。當搜尋沒有找到任何結果時，表格會顯示 `沒有相符的 Block。請嘗試減少執行個體數量、改用其他期間，或增加區域。`，並附有**有方案時提醒我**連結。

表單上方的**最近的搜尋**會以標籤顯示您最近五次的搜尋，只保留在此瀏覽器中。**建立到貨提醒**會開啟一個對話方塊，顯示區域與類型組合的數量、執行個體數量和期間，然後為每組組合新增一個提醒。它會略過您已有的提醒，並在達到您的提醒上限時停止。

### 最大容量

選擇**區域**、**執行個體類型**和**期間（天）**，然後選擇**尋找最大容量**。頁面會找出有方案的最大執行個體數量（1 到 64），並顯示該數量的最早開始時間、結束時間、可用區域和預付費用。頁面最多會傳送三個縮小範圍的請求，因此結果大約需要 10 到 20 秒。`目前沒有可用容量` 表示 EC2 沒有列出該長度、數量在 1 到 64 之間的 Block。請嘗試較短的期間或其他區域，或在**搜尋可用性**建立到貨提醒。

## 配額索引標籤

**配額**索引標籤顯示其頁首所選區域的配額：P、G 與 VT、Trn 以及 Inf 執行個體系列的隨需和 Spot vCPU 配額，以及各系列的 Capacity Block 配額。每個群組都有自己的表格和簡短說明。如果您之前使用過某個執行個體類型，適用於其系列的配額會在每個群組中排在最前面，並以醒目方式標示。將滑鼠移到配額名稱上、以鍵盤聚焦，或點選它，即可顯示說明用量計算內容的提示。按 Esc 可關閉提示。

| 欄 | 意義 |
|---|---|
| **配額** | Service Quotas 回報的配額名稱。`無法調整` 標記表示您無法申請提高。Capacity Block 列帶有 `僅上限` 標籤。 |
| **上限** | 配額值及其單位，例如 `192 個 vCPU`。`AWS 預設值` 標記表示 Service Quotas 未傳回您帳戶的套用值，因此頁面顯示 AWS 預設值。 |
| **過去一小時的已使用量（此帳戶）** | 僅限隨需和 Spot 列。部署本範例之 AWS 帳戶過去一小時內的最高用量，來自 Amazon CloudWatch 用量指標，並附有長條圖和佔上限的比例。達到 80% 時，長條會變成黃色，儲存格顯示 `接近上限`；達到 100% 時會變成紅色，並顯示 `超過上限`。 |
| **連結** | **在 Service Quotas 中檢視**會在新索引標籤中開啟該區域 Service Quotas 主控台中的此配額。 |

當某個配額已達到或超過上限時，表格上方的通知會說明：需要更多此配額的啟動會失敗，直到用量下降或上限提高。AWS 不公布 Capacity Block 配額的用量指標，因此其表格只顯示上限。用量指標可能比實際使用延遲幾分鐘。**重新整理**會再次向 Service Quotas 和 CloudWatch 查詢。此索引標籤一次檢查一個區域，且為唯讀。若要申請提高配額，請使用**在 Service Quotas 中檢視**連結。

## 提醒索引標籤

此索引標籤會在管理員開啟電子郵件提醒時出現。當某個訊號從無法使用變為可用時，提醒會寄電子郵件給您。提醒只讀取訊號；它們不會執行測試啟動，也不會預留任何項目。

1. 在表單中選擇**區域**。它會從您上次使用的選擇開始。
2. 選擇**訊號**：
   - **Capacity Block 方案**、**天數**，以及 1 到 64 的**執行個體數量**。當 EC2 為該數量和長度列出 Capacity Block 方案時，提醒會變為可用。
   - **Spot 放置分數**和**分數至少為**，1 到 10。下一個清單會變成**分數群組**：選擇該區域提供的群組，例如 `g6e · 4 個 GPU`。當該群組的區域分數達到您的門檻時，提醒會變為可用。它涵蓋管理員為 Spot 分數選擇的系列，並跟隨每 15 分鐘的重新整理。
3. 對於 Capacity Block 提醒，請選擇**執行個體類型**。選擇**新增提醒**。若要一次為多個區域和類型新增 Capacity Block 提醒，請使用 **Capacity Block** 索引標籤上的**建立到貨提醒**。
4. 新增第一個提醒時，黃色通知會請您確認訂閱。開啟來自 AWS Notifications 的電子郵件，然後選擇 **Confirm subscription**。您只需要確認一次。電子郵件會寄到您使用者的地址。

在您確認之前，您不會收到任何提醒電子郵件。提醒會保留其狀態，因此如果您確認後的第一次檢查時訊號仍然可用，電子郵件就會在那時寄出。Amazon Simple Notification Service（Amazon SNS）會刪除 48 小時內未確認的訂閱。如果發生這種情況，請刪除您的提醒並重新新增，以取得新的確認電子郵件。

| 欄 | 意義 |
|---|---|
| **區域**、**執行個體類型** | 提醒檢查的對象。對於 Spot 分數提醒，**執行個體類型**欄會顯示分數群組。 |
| **訊號** | `Capacity Block，N 個執行個體，N 天` 或 `Spot 分數至少為 N`。 |
| **狀態** | `等待首次檢查`、`無法使用`、`目前可用`，或 `EC2 不接受此提醒（...）` 並附上原因，例如 EC2 未為該類型提供該期間或執行個體數量時。被拒絕的提醒不會寄送電子郵件；請刪除它，並新增一個 EC2 接受的提醒。 |
| **上次檢查** | 上次檢查距今多久，或 `尚未檢查`。 |
| **刪除** | 在確認對話方塊之後移除提醒。 |

索引標籤頂端的說明會以管理員設定的檢查間隔開頭，例如 `每 15 分鐘檢查一次提醒。`。檢查依排程執行，因此在兩次檢查之間出現又消失的訊號不會寄送電子郵件。提醒寄出電子郵件之後，只有在訊號變為無法使用、然後再次變為可用時，才會再次寄送。當您刪除最後一個提醒時，頁面也會移除您的電子郵件訂閱。若要停止寄送提醒電子郵件到您的地址，請選擇提醒電子郵件中的取消訂閱連結。

## 使用者索引標籤

**使用者**索引標籤僅為說明：它不呼叫任何 API，也不顯示任何使用者資料。它說明如何在 Amazon Cognito 主控台中新增、更新和刪除使用者，使用者就是在那裡管理的。選擇**開啟 Amazon Cognito 主控台**，即可在新索引標籤中開啟此部署的使用者集區。這需要開啟使用者集區的 AWS 權限；如果您沒有權限，請洽詢您的管理員。一般使用者不需要此索引標籤。

## 決策手冊

### 情境 1：需要預留容量的多週訓練

您需要某種類型的數個執行個體，為期三週，且容量必須在訓練開始時就緒。

1. 在 **Capacity Block** 上，勾選您可以使用的區域和類型，將**期間（天）**設為 `21`，將**執行個體數量**設為您需要的數量，然後選擇**尋找 EC2 Capacity Block**。在**配額**中確認有足夠的 Capacity Block 配額。
2. 比較**開始**、**每執行個體小時**和可用區域，然後在合適的列上選擇**在 EC2 主控台購買**。請盡快購買；方案可能被其他客戶買走。
3. 如果沒有相符的結果，請針對一個區域嘗試**最大容量**，或嘗試相近的期間，例如 `14` 或 `28`，或選擇**有方案時提醒我**。收到電子郵件時，選擇**重新搜尋**或最近搜尋的標籤。

### 情境 2：彈性的 Spot 批次工作

您的工作可以在多個不同的區域和可用區域中執行，並且可以停止和重新開始。

1. 在 **Spot 分數**上，找到您需要的 GPU 群組所在的欄，尋找分數高（`7 至 10`）的區域。比較提示和區域詳細資料中的 Spot 價格。在**配額**中確認該區域有可用的 Spot 配額。
2. 在最佳區域的區域詳細資料中選擇**測試啟動**（它會開啟**隨需與 Spot**索引標籤），選擇群組（或一個尺寸），選擇 Spot，然後執行測試啟動。結果會告訴您 EC2 挑選的可用區域和尺寸。
3. 如果沒有任何區域的分數夠高，請在**提醒**索引標籤上新增 **Spot 放置分數**提醒，並設定您可接受的門檻，例如 `7`。

### 情境 3：我遇到配額錯誤

測試啟動或您自己的啟動傳回了 `配額上限` 或 `VcpuLimitExceeded` 之類的錯誤，或頁面表示您的配額可用量太少。

1. 為發生問題的區域開啟**配額**。您上次使用之類型的配額會在每個群組中排在最前面。
2. 比較**過去一小時的已使用量（此帳戶）**和**上限**。`接近上限` 或 `超過上限` 表示幾乎沒有或完全沒有餘裕。有效的 Capacity Reservation 會計入隨需配額。
3. 在頁首選擇另一個區域以尋找餘裕，或選擇**在 Service Quotas 中檢視**以申請提高配額。`無法調整` 的配額無法提高。用量可能延遲幾分鐘；在您結束執行個體之後，請選擇**重新整理**。

## 費用與安全注意事項

- 測試啟動會啟動一個真實的執行個體數秒鐘，然後終止它。隨需測試會依該執行個體類型的最短計費期間計費。Spot 測試也可能產生費用。請在最大的執行個體類型上節制地測試。
- 冷卻時間會將每個群組或尺寸、市場和區域，限制為在時間範圍內跨使用者只啟動一次。每日上限會限制您的使用量，以及整個部署的使用量。
- 頁面顯示定價和最新的 Spot 價格。您實際支付的金額可能不同，例如因折扣、Savings Plans 或稅費而異。
- 您在 EC2 主控台購買的 Capacity Block 是一項購買。您以**使用 CLI 預留**複製的命令會建立 Capacity Reservation，從建立起就依隨需費率計費，直到它結束或您取消為止。頁面不會追蹤或取消其中任何一項。
- 每個結果都是特定時間點的結果。`已啟動` 的結果或方案不會預留任何項目，而 Spot 放置分數是一種可能性。

## 疑難排解

| 症狀 | 處理方式 |
|---|---|
| 臨時密碼無法使用 | 它會在七天後過期。請管理員寄送新的密碼。請完全依照電子郵件中顯示的內容輸入。 |
| 驗證器驗證碼被拒絕 | 確認手機上的時間設為自動設定。在驗證碼變更之前輸入目前的驗證碼。如果您遺失了裝置，請洽詢您的管理員。 |
| 忘記密碼 | 在登入頁面選擇 **Forgot your password?**，並使用寄到您電子郵件地址的驗證碼。 |
| 頁面顯示 `請登入以繼續。` | 選擇**登入**。 |
| `無法載入頁面。` | 頁面無法連線到 API。選擇**重試**。如果重複發生，請洽詢您的管理員。 |
| 長時間閒置後頁面將您帶到登入頁面，或動作失敗並顯示 `您的工作階段已過期。` | 您的工作階段已結束。工作階段預設最長為 12 小時，關閉瀏覽器索引標籤也會結束工作階段。請重新登入，然後重複該動作；過期的請求並未送達 API 函式，因此沒有啟動任何項目。 |
| 帶有**重試**的紅色訊息 | 索引標籤的該部分未載入。選擇**重試**。訊息會指出是哪個部分並說明原因。 |
| 頁面顯示 `正在為此部署設定 Spot 分數` 或表示群組正在建立 | 首次部署後，或管理員變更 Spot 分數系列後，部署會在第一個請求時建立群組，約需一分鐘。索引標籤保持開啟時，頁面每分鐘會再次讀取群組並自動更新。 |
| 表格顯示 `此部署沒有 Spot 分數群組` | 群組已建立，但為 Spot 分數選擇的系列在已啟用的區域中都沒有提供。請管理員檢查 `spotScoreFamilies`。 |
| 儲存格顯示 `下次每日更新後取得 Spot 分數` | 該區域提供群組中的某個尺寸，但會在下次每日更新（00:30 UTC，以您的當地時間顯示）時加入群組。您不需要做任何事。儲存格顯示 `–`，游標停留時會出現此文字。 |
| 某個群組或系列沒有欄 | 管理員會選擇取得 Spot 分數的系列。請他們將該系列加入 `spotScoreFamilies`。供應、價格、配額和測試啟動仍涵蓋該系列。 |
| 儲存格顯示 `–`，但該區域提供此群組 | 分數會在下次重新整理時取得（每 15 分鐘），或部署每日的 Spot 分數請求預算尚無額度，請求正在等候。這不是錯誤。 |
| 儲存格顯示 `•`，並顯示 `AWS 沒有傳回此區域的 Spot 分數` | AWS 已回應請求，但回應中不含此區域。這不是錯誤，也不是限制，等候也不會改變。請執行測試啟動來確認該區域。 |
| Spot 分數很高，但測試啟動失敗 | 這是正常的。分數是對那一刻的估計，等到您啟動時容量可能已經消失。請再試一次，或嘗試另一個區域。請參閱[如何使用 Spot 放置分數](#如何使用-spot-放置分數)。 |
| Spot 分數很低，但測試啟動成功 | 這也是正常的。低分仍可能啟動。請以測試啟動作為真正的確認。 |
| `此區域沒有預設 VPC` | 測試啟動使用預設 VPC，而此區域沒有。請洽詢您的管理員，或測試另一個區域。 |
| `您的「...」配額尚有 ... 可用，而最小的尺寸需要 ...` | 群組中沒有任何尺寸符合您在該市場的可用 vCPU 配額，且未啟動任何執行個體。請參閱[情境 3](#情境-3我遇到配額錯誤)。 |
| 測試啟動表示您已達到每日上限 | 管理員會限制每位使用者每天的測試啟動次數，以及整個部署的次數。每個送達 EC2 的請求都會計入。計數會在 00:00 UTC 重設（頁面會以您的當地時間顯示）。請在重設後再試，或請管理員提高 `maxTestLaunchesPerUserPerDay` 或 `maxTestLaunchesPerDay`。 |
| 某個區域顯示 `未啟用` | 帳戶尚未啟用該區域（需選擇加入的區域）。請洽詢您的管理員。 |
| 某個區域顯示 `該區域未回應。` | 該區域的 EC2 端點未及時回應。部署會略過該區域 5 分鐘。請在幾分鐘後再試；如果持續發生，請告知您的管理員，管理員可以排除該區域。 |
| `服務目前忙碌中。請稍候，然後選擇「重試」。` | 許多人同時使用此頁面，而 API 速率限制適用於所有人合計的請求。請稍候片刻，然後選擇**重試**。如果重複發生，請管理員提高速率限制。 |
| `同時的請求過多。請稍候，然後選擇「重新整理」。` | 某個動作（例如測試啟動）達到了 API 速率限制。頁面不會重複會啟動或變更某些項目的動作，因此沒有任何動作執行兩次。請稍候片刻，然後再次選擇該動作。 |
| `此資料不到一分鐘前剛重新整理過，因此您看到的是該次的結果。` | 有人在過去一分鐘內重新整理了相同的資料，而每個人共用這份資料。請在說明中的秒數過後再次選擇**重新整理**。 |
| 資料看起來比我預期的舊 | 閱讀 `更新於` 標籤。Spot 分數每 15 分鐘重新整理一次。其他超過快取時間的資料，會在您開啟索引標籤或回到頁面時重新載入。 |
| **提醒**索引標籤不見了，或**隨需與 Spot**索引標籤沒有測試啟動面板 | 管理員關閉了該功能。 |
| 沒有收到提醒電子郵件 | 確認來自 AWS Notifications 的訂閱電子郵件，並檢查您的垃圾郵件資料夾。只有當提醒的狀態從無法使用變為可用時，提醒才會寄電子郵件給您。請查看**提醒**索引標籤上的**狀態**和**上次檢查**。 |
| 確認電子郵件已超過 48 小時，或您使用了取消訂閱連結 | SNS 已移除訂閱。請刪除您的提醒並重新新增，以取得新的確認電子郵件。 |
| 新增提醒時顯示 `您的電子郵件地址尚未驗證。` | 請管理員將您的電子郵件地址標示為已驗證。 |
| `您已有這個提醒。` | 已存在區域、類型、訊號和值都相同的提醒。區域、分數群組和門檻相同的 Spot 分數提醒，會視為同一個提醒。 |
| `此執行個體類型不支援 Capacity Block 提醒。` | 請選擇屬於 Capacity Block 系列的類型。 |
| **Capacity Block** 索引標籤上顯示 `<type>：Capacity Block 不支援（<Region>）` | EC2 在該區域不為該類型提供 Capacity Block。請選擇另一個類型。 |
| `EC2 目前不接受此類型 N 天的 Block` | EC2 在那一刻拒絕了該期間。請嘗試較短的期間。 |
| **尋找 EC2 Capacity Block** 一直無法使用 | 閱讀旁邊的原因：至少選擇一個區域和類型、1 到 64 的執行個體數量、最多為今天（UTC）起 14 天內的最早開始日，且區域與類型組合最多 40 組。 |

## 詞彙表

| 詞彙 | 意義 |
|---|---|
| Capacity Block | Capacity Blocks for ML：您購買的 GPU 執行個體，期間固定，從 1 天到最多 182 天，從未來的某個日期開始，位於單一可用區域。 |
| 分數群組 | 一個執行個體系列搭配一種 GPU 數量，例如 `g6e · 4 個 GPU`。群組的 Spot 分數是區域層級的機會，代表針對任一列出尺寸的 Spot 請求被滿足的可能性。 |
| Spot 放置分數 | EC2 為某個區域傳回的 1 到 10 分數。分數越高，表示 Spot 請求越可能成功。它是一種可能性，而不是承諾。 |
| 每日更新 | 在 00:30 UTC 執行，將新尺寸、區域和群組加入 Spot 分數群組的作業。 |
| 定價 | AWS 公布的公開價格，未計入折扣、Savings Plans 或稅費。 |
| 配額 | 您的帳戶在一個區域中可使用的資源數量限制，例如執行中 P 執行個體的 vCPU。即使有容量，配額也可能阻擋啟動。 |
| 測試啟動 | 啟動一個執行個體，並由頁面在啟動呼叫之後立即終止，以了解在那一刻是否有容量。管理員指南和 API 稱之為啟動探測（launch probe）。 |
| 冷卻時間 | 在這段分鐘數內，對相同群組或尺寸、市場和區域重複測試時，會傳回先前的結果。 |
